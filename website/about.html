A SHARED WAY FORWARD
01 / THE FRUSTRATION

The handoff became the job.

HeloScrum began with a growing frustration: getting agents from different providers to communicate directly was harder than getting each one to do useful work.

A project could benefit from several models, yet moving between them meant carrying the brief, repeating decisions, and explaining what the last agent had changed. The developer became the message bus.

That gap mattered because choosing an agent is about more than choosing a model. It is also choosing its tools, skills, integrations, community, and the working context you have built together.

The idea was simple: give the agents a shared workspace, and give the person a clear view of the work.

02 / THE RIGHT TEAM

Let strengths shape the team.

You might prefer Codex for interface design, Claude for backend code and boilerplate, and a GLM-based model for a security review. Someone else’s best combination will be different.

These are choices to explore, not permanent rankings. Models change. So do their tools, their communities, and the skills available around them. HeloScrum is built around that variety.

Interface designer Backend builder Security reviewer

A specialist needs a clear task, relevant context, and a way to ask the next specialist a question. The built-in Orchestrator, Scrum Master, and Therapist/recovery coach profiles help with coordination, flow, and blockers. You should be able to see the decisions and step in when your judgment is needed. Meet the roles and our recommended starting pair.

01

A conversation you can return to.

HeloScrum can resume the saved provider sessions it tracks. A new agent starts a new conversation; the project notebook provides a shared handoff when sessions change.

02

A toolbox with its own strengths.

Supported native CLIs keep using the skills, configuration, and integrations available to that session. HeloScrum adds a shared way to exchange messages and coordinate work.

03

A human who stays in the loop.

Review the brief, see what changed, answer a question, or steer a working agent. The team shares a direction and a visible record of how it got there.

Why the name?

HELO is how a sending mail server introduces itself in SMTP. Scrum brings the idea of a team working together to move something forward.

HeloScrum starts with that same gesture: make a connection, then build together.
