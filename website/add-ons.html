HOW WE USED CLAUDE MODS

One event, two useful views.

Claude’s Mod observes a tool event and reports it through the session’s authenticated HeloScrum connection. Our web renderer turns that record into a card; the Mod draws its own native panel inside Claude Code.

Herdr keeps the native session connected. HeloScrum handles the web presentation and saved history. Reported test results remain distinct from independent task verification. Read the implementation story.

INCLUDED. YOUR CHOICE TO USE.

A small addition to
your Claude setup.

HeloScrum bundles the visual Mod and loads it for new, compatible Claude Code sessions unless disabled. It requires no global plugin installation. The base activity view makes no model requests; optional Jev Auto role selection records its bounded requests and usage.

Full setup & behavior ↗

The source and setup guide are available on GitHub under Apache-2.0.

01

Use a compatible Claude Code CLI.

The current public Mod documentation requires 2.1.287+. HeloScrum was also tested on 2.1.286 with its function-hook flag enabled by the launcher.

Claude Mod documentation ↗
02

Launch a Claude Code agent.

Start it through HeloScrum, then open its Chat view. For an existing session, wait until work is idle before relaunching to load the Mod.

03

Open your native panel, too.

Run /heloscrum in the interactive Claude terminal. Choose Pin status strip to keep a compact view, or close the panel with Escape.

Prefer to leave it off?

Before starting the HeloScrum server from your checkout:

HELOSCRUM_CLAUDE_ACTIVITY=0 npm start

This applies to newly launched sessions. Existing processes keep their configuration. Explicit Claude hook-disable settings are respected; normal transcript reading remains available. The base activity Mod has no per-agent switch; optional role packs have their own Off setting.

Connect through Claude Code. Choosing a Claude model in Cursor, Kiro, or an API connection does not load Claude Code Mods. Your tool permissions and task-review rules still apply.

OPTIONAL AUTO SELECTION · POWERED BY JEV

The role gives context. You keep control.

Jev selects relevant installed packs from an agent’s duties and current brief. Choose Off, Manual, or Auto, with visible judgments and manual pins. If the match is unclear, keep the base view.

Off is the default. Manual selection needs no Jev connection. Auto is opt-in and records actual judgments and usage. One builder can wear more than one hat. Role packs adapt that builder’s workspace without requiring more agents.
