A HAND GETTING STARTED

Set Up With Your AI

Already working with a coding agent? Give it this prompt. It can check your computer, help with installation, and show you how the workspace fits together.

FOR YOUR CODING AGENT
Help me install and learn HeloScrum: https://github.com/YokiiDesu/heloscrum.
Read README.md, docs/INSTALLATION.md, and docs/AI_SETUP.md from that repository
or my existing checkout first. Detect my OS, architecture, and shell, explain
its current support status, and check the prerequisites. Use the documented
installer for my platform and preserve my existing projects and configuration.
Leave provider sign-in and permission choices to me. Verify local startup,
then guide me through opening a project, connecting agents, assigning a small
task, sharing attachments, and reviewing the result. Explain what was actually
verified and anything that still needs my input.

Use an agent with terminal access. The source is public; your agent can read the repository or your existing checkout. You'll handle provider sign-in and permission choices yourself.

01 / BRING YOUR TOOLS

A local setup, with your accounts.

Start on macOS, where the local alpha has been checked. Automated tests also run on Linux; native Linux and Windows provider workflows still need validation.

  • Node.js 22.13 or newer and npm. Node 24 is a good starting point.
  • Git, with your name and email configured for commits.
  • A supported provider CLI, installed and signed in separately, or a tool-capable model endpoint. Our local LLM guide walks through llama.cpp and Muse Glimmer.
  • Herdr 0.9.0, required by desktop setup and native provider sessions. The installer offers a verified download. Provider login happens separately.

Docker, Jev, and a summary model are optional. Your provider account or model server handles inference and its associated usage.

CHOOSE YOUR PLATFORM

What Your Computer Needs

The installer detects macOS or Linux and your CPU architecture automatically. Both use the same Bash script. WSL uses the Linux route.

macOS Desktop Alpha

Apple Silicon or Intel. You'll need Git from Apple's Command Line Tools, Terminal, and an internet connection. Setup offers Node, required Herdr, Electron, and provider tools.

If Git is missing, run xcode-select --install and finish Apple's installer first.

Linux Experimental Desktop

ARM64 or x64, with Git, Bash, curl, tar and a SHA-256 tool. Electron needs X11/Wayland plus GTK, NSS, GBM, XSS and ALSA. Setup can offer apt/dnf packages with your approval.

Native builds may also need Python and a C++ toolchain. Server and automated checks pass; a complete native desktop/provider workflow still needs verification.

Windows / WSL 2 Experimental Linux Route

Install WSL 2 with Ubuntu using Microsoft's instructions. Open Ubuntu, keep the checkout in your Linux home directory, and run the Bash installer there. WSLg is needed for the desktop window.

Sign in to provider CLIs inside WSL. This doesn't validate native Windows. Without a Linux GUI, use the browser setup below.

Native Windows Contributor Checks Only

There isn't a supported native Windows desktop installer yet. Herdr's direct terminal-attach command, used by the embedded provider terminals, is unsupported on Windows.

Contributors can install Node.js 22.13+ and Git for Windows, then run npm ci and npm run test:platform in PowerShell. See the current limitation and testing instructions.

02 / START HELOSCRUM

Install. Check. Open.

The source is available on GitHub. Setup runs on your computer.

On macOS, Linux, or inside Ubuntu on WSL, open a terminal and run:

DESKTOP SETUP
git clone https://github.com/YokiiDesu/heloscrum.git
cd heloscrum
bash scripts/setup-desktop.sh
↳ Follow the prompts. Setup creates a launcher.

You'll see seven stages, download progress, questions, and the log location. Setup reuses compatible tools or offers a private runtime. It doesn't sign in to your provider or start paid agent turns.

Use the Browser Instead

Install Node.js 22.13+, Git, Herdr and your chosen provider first. From the checkout:

BROWSER SETUP
npm ci
npm run doctor -- --provider codex
npm start

Replace codex with your provider. Open http://127.0.0.1:4173 and leave the terminal running. Doctor checks dependencies without an AI call. If the engine is offline, choose Start Engine.

03 / OPEN A PROJECT

Give the team a place to work.

Choose the project name in the header, or press ⌘ / Ctrl + Shift + P, to open the project library. In the desktop app, Open Local Folder opens your OS folder chooser. Choose a Git repository, or review Initialize Git & Open for a new folder. Its first commit is empty; your files stay untracked and nothing is uploaded.

For a first run, use a small disposable repository. Create a Builder and a Reviewer under Agents → Add agent. They can use different providers; give each a clear role and an appropriate effort setting.

A USEFUL STARTUP PROMPT

Introduce yourself in one sentence, then stop. Wait for an assigned active task before editing files.

Creating an agent starts a provider session. Answer any provider login, trust, or permission prompts before submitting work.

04 / TRY A FIRST TASK

One builder. One fresh pair of eyes.

In Tasks → New task or plan, choose A task, select both agents, and use Direct assignment. Assign the Builder as owner, set the Reviewer as QA lead, and choose Ask for my review with Adaptive · Kanban.

FIRST TASK / A SMALL, TESTABLE CHANGE

Build a slug helper.

Create a dependency-free JavaScript function that lowercases ASCII letters, trims whitespace, turns runs of spaces into one hyphen, and removes other punctuation.

" Hello World! "→"hello-world"

Definition of done

  • The helper and focused Node tests are saved in the project.
  • Empty input, repeated spaces, and punctuation are covered.
  • The reviewer runs the checks and records the result.
  • You inspect the evidence and diff before accepting the work.

Save a draft to review the brief, then choose Review & start. Watch the handoff reach Needs review; completing the task and committing or merging code are separate decisions.

WHEN THE FIRST HANDOFF WORKS

Build the workflow that suits you.

Keep one builder and one independent reviewer for a small local app. Add a specialist when the project has a specific need and a clear responsibility to hand over. Introduce a dedicated coordinator when managing several active owners becomes substantial work.
