Giving Claude’s work a visible shape

How we used Claude Code Mods to turn reported tool activity into readable cards, native panels, and focused role views.

By HeloScrum

IN THIS ARTICLEFrom output to a readable resultTwo views of the same workA workspace for the responsibilityA more natural conversation

From output to a readable result

The first version could report what Claude was doing. It was useful plumbing, but the experience still looked like more raw terminal text. We wanted the result to be understandable at a glance, with enough detail nearby to check it.

A test run became a card with named cases, pass/fail/skip counts, and an outcome bar. An edit became a before-and-after view. Reported context measurements became a gauge. The command, output, and timing remain available inside each card.

Those presentations are tied to the event we actually received. A successful shell exit alone cannot become “all tests passed.” A proposed edit cannot become a completed change before its result arrives. Missing measurements stay unknown.

Two views of the same work

Claude Code Mods run event handlers inside Claude Code. They can observe activity and draw native interface elements. We built a Mod around those extension points; we did not fork Claude Code or replace its model.

  1. 01Observe a tool eventThe Mod records a tool start or result while the native operation continues.
  2. 02Report through the sessionThe event travels over the agent’s existing authenticated HeloScrum MCP connection.
  3. 03Render it where you workHeloScrum draws the web card and preserves activity in History. The Mod also draws a native panel inside Claude Code.

Herdr supplies the persistent native-session connection. HeloScrum supplies its own web interface, activity records, and task system. The native /heloscrum panel provides Activity, Changes, Context, and optional Roles views, with a status strip you can pin above the prompt.

This distinction matters for a custom interface: a Mod’s native pane does not automatically appear in a browser or in headless output. Our browser cards are a separate renderer over the reported records. Anthropic documents the supported rendering surfaces.

Activity is evidence, with a source.

A reported test result tells you what the tool reported. Independent review and final task acceptance remain separate steps. The base activity bridge makes no extra model requests and does not approve tool permissions.

A workspace for the responsibility

The eight role packs focus an existing Claude agent’s view on orchestration, Scrum flow, UI/UX, game design, independent QA, data architecture, DevSecOps, or knowledge management. They show recorded criteria, references, findings, and review evidence alongside a concise guide.

A Knowledge Manager can keep SOPs, document standards, tags, versions, and review ownership in view. A reviewer can separate the author’s claims from independent findings. One builder can use several packs without creating a team of extra agents.

Selection defaults to Off. Manual selection needs no Jev connection. Optional Jev Auto selection matches the assigned duties to installed packs and exposes its judgments and usage. Selecting a view does not grant task authority or run the checks shown in it.

A more natural conversation

Readable activity cards also leave room for readable conversations. “Found one: reloading loses the filter. Here are the steps” is easier to follow than a stream of status fields. “Good catch. I fixed the save boundary; could you recheck this candidate?” is warm and still useful.

That is the direction of our new scripted website demos. They model direct questions, specific appreciation, candid uncertainty, and concise handoffs. They are illustrations, not transcripts of measured agent runs. Separately, project conversation settings now let users choose concise, conversational, or expressive guidance for newly started sessions and subsequent delivered messages.

Natural language should carry the facts. It should not invent a result, manufacture an emotional state, or start a chain of acknowledgment-only replies. Names, task state, candidate revisions, and evidence can stay in structured records while the conversation sounds like collaborators talking.

Explore the visual Mod and its interactive examples. The add-on is included in the public HeloScrum checkout.
