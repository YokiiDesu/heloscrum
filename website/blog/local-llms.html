The Settings That Produced This Demo

There are three parts: Muse Glimmer is the model, llama.cpp runs it, and HeloScrum gives the agent its workspace and tools. You start the model server, save its address in HeloScrum, and choose that connection for your agent.

This run used the LM Studio Community GGUF of Muse Glimmer. We reused an existing download, unloaded the model in LM Studio, and loaded those files in llama.cpp.

These are the settings we used, not minimum hardware requirements. A smaller model or shorter context may be a better fit for your computer. Leave memory for the operating system, HeloScrum, and the model’s working context.

1. Install llama.cpp

Start with the llama.cpp GitHub repository, its official website, or the prebuilt releases. The commands below follow the project’s installation guide.

macOS · WITH HOMEBREW INSTALLED
brew install llama.cpp
llama-server --version

Windows

In PowerShell, install through WinGet, then open a new terminal if the command isn’t found:

winget install llama.cpp
llama-server --version

You can also download the Windows build for your hardware from the releases page. Keep its executable and accompanying libraries together. Run .\llama-server.exe from the extracted folder.

Linux

Use a matching prebuilt release, an existing Homebrew installation, or follow the official build guide. With Git, CMake, and a C++ compiler installed, a basic source build is:

git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release -j 4
./build/bin/llama-server --version

The build guide covers CUDA, Vulkan, and other acceleration options. Choose the backend for your hardware before building.

This article’s measured example is on macOS. Installing llama.cpp on Windows or Linux doesn’t by itself verify HeloScrum’s full desktop workflow there; see HeloScrum’s platform notes.

2. Get the Model Files

Open the Muse Glimmer GGUF file list and download the model and matching projector shown in our settings table. Read the model card and its terms before choosing it for your work. The two downloads total about 18.2 GB.

If you already have these GGUF files, point llama.cpp at them. You don’t need another copy just because you used a different app to download them. An MLX-format download isn’t a GGUF file, though, so check the format.

The projector adds image input for compatible models. This red-ball task only used text. For a text-only setup, omit --mmproj and leave image input off in HeloScrum. See llama.cpp’s multimodal guide for supported pairings.

3. Start the Model Server

This is the launch configuration from our run, with personal file paths replaced. Change /path/to/models to the folder holding your files, then paste the command into a macOS or Linux terminal.

THE RECORDED SERVER CONFIGURATION
llama-server \
  --model "/path/to/models/Muse-Glimmer-30B-KQuant-17GB-Q4_K_M.gguf" \
  --mmproj "/path/to/models/mmproj-Muse-Glimmer-30B-Q4_K_M.gguf" \
  --alias meta/muse-glimmer \
  --host 127.0.0.1 --port 8080 \
  --ctx-size 32768 --parallel 1 \
  --gpu-layers all --flash-attn on \
  --cors-origins localhost --no-ui --offline --log-colors off

On Windows, use llama-server.exe, Windows file paths, and put the command on one line instead of using the backslash line breaks. A source build may need the full path to the executable.

Wait for the server to report that its model is loaded and it’s listening. Keep that terminal open. Press Ctrl+C when you’re done to stop the server and release its memory.

The alias is the model name HeloScrum will select. The context limit is 32,768 tokens and the server runs one request at a time. All-layer GPU offload and Flash Attention are the settings that worked on our Mac; adjust them for your hardware using the server reference.

--offline uses the supplied files without fetching a model. The address stays on this computer. HeloScrum supplies the agent tools, so this command doesn’t enable llama.cpp’s own agent or built-in tool mode.

4. Save the Connection in HeloScrum

  1. Open Settings → AI & Context → Add Connection. Choose llama.cpp.
  2. Name it llama.cpp · Muse Glimmer. Set the API base URL to http://127.0.0.1:8080/v1.
  3. Click Discover Models and select meta/muse-glimmer. Discovery lists models without sending project content or running inference.
  4. Set Model Context Window to 32768 and Maximum Output Tokens to 8192. These limits should match your server and leave room for instructions, tools, and replies.
  5. Enable tool calling for a coding agent. Enable image input only if you loaded a compatible vision model and projector. Save the connection.
  6. Use Test Connection for a short generation check. Then choose this provider, model, and connection in your agent’s settings.
Already Seeing a Green “Connected” Indicator?

Your saved connection’s model catalog is reachable. You can use that connection; there’s no need to set it up again. Manage it in AI & Context if you need to change it. Unused duplicates can be archived and restored later.

“Connected” checks availability. A small test task is still the useful next check for tool calling and coding behavior. HeloScrum doesn’t start the model server for you.

If you’re switching an existing agent, wait for it to finish or interrupt it, choose the new connection, and click Review Change. Review the handoff, then choose Start Fresh With This Handoff. The agent keeps its workspace and receives the reviewed context in a new provider session.

127.0.0.1 means the computer running HeloScrum’s backend. If the backend is in a container or on another computer, use an address it can reach. Keep the server private and configure authentication before sharing it beyond loopback.

For a new run, open a small test project, add a Builder using your local connection, and give it the brief. Ask it to save the result as a self-contained index.html. Open that file and try dragging and throwing the ball. Review any command requests as they appear; local inference doesn’t change the tools’ access to your computer.

Our recorded run resumed an existing Builder after a provider change, with the brief and earlier context in its handoff. Copying the brief into a fresh session is a useful starting point, but the output and timing can differ.

Try the result above or download the original HTML. The download is the exact 4,862-byte file written by Muse. The embedded version adds a restrictive security policy around the same HTML. Its CSS, JavaScript, physics, and controls are unchanged.

If Something Gets Stuck

“Not Connected” or No Models Listed

Check that the server is running, the port matches, and the URL ends in /v1. We explicitly selected port 8080; other llama.cpp launchers or versions may use another port. Use the address your server prints, then try Discover Models or Check Again.

“Waiting For Model” Takes a While

Check the server log and memory use. Loading a large model, processing a long prompt, or waiting behind another request can take time. Start with one active agent. If you switched runtimes, unload unused models in the other app so two copies aren’t competing for memory.

A Timeout or an Unfinished Reply

HeloScrum allows five minutes for local generation to start, two minutes without activity after it starts, and thirty minutes overall for one response. Active generation can continue beyond ninety seconds. If it hits the output limit, increase the output budget or reduce the model’s reasoning budget. Interrupt stops the current request; check completed tool actions before trying again.

The Model Chats but Doesn’t Use Tools

Check the model’s tool support and its chat template in the server. Enabling a checkbox doesn’t teach a model tool calling. Try a small file-writing task first, then expand the work once that succeeds.

Already Using Another Local Runtime?

LM Studio is another supported connection. Load a suitable model, start the API server from its Developer tab, and save an LM Studio connection using its displayed address, commonly http://127.0.0.1:1234/v1. An open chat window alone doesn’t start the API server. Follow the official server setup guide.

HeloScrum also supports Ollama through its compatible API. The same pattern applies: start the runtime, load a tool-capable model, discover it, and save a named connection.

For this example, llama.cpp with Muse Glimmer worked well. If your existing runtime is already working, you can keep it. Pick the model and server combination that fits your hardware and the work you want to do.
